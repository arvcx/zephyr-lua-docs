Zephyr Scripting API

Scripting reference for Zephyr bots. Scripts are plain Lua files with full access to the bot fleet, the world model, automation, and the item catalogue.

Getting started

  • Scripts are .lua files placed in the scripts/ folder beside Zephyr.exe.
  • Open the Executor page to browse, run, stop, and edit scripts. Hot reload picks up saved changes while a script runs.
  • A script is bound to a bot (the one selected when it starts, or the bot you pass). getBots() reaches the whole fleet.
  • A script error is printed to the console and the script stops.
-- scripts/hello.lua
print("Zephyr " .. zephyrVersion())

local bot = getBot()
print(bot.name, bot.status)

Script model

  • One cooperative body per script: sleep(ms) yields the script, so the window keeps drawing. Never busy-wait.
  • Timers: after(ms, fn) fires once; every(ms, fn) repeats. Both return a handle for stopTimer(handle).
  • Long walks yield too: bot:findPath(x, y) suspends the script until the bot arrives.
  • Event handlers run serialized with the script body.
every(5000, function()
    if bot.status == BotStatus.online then
        bot:say("heartbeat")
    end
end)

Getting bots

CallResult
getBot([nameOrId])A bot object. No argument = the script's own bot
getBots()Array of every bot
getBotId()Id of the bound bot, or 0
addBot{ name=, ltoken= }Create a bot from a token. ltoken may be spelled token or secret. Returns the bot object, or nil, error
addBot{ name=, password= }Create a bot that signs in with GrowID + password
addBot("name"), addBot("name", "token")String spellings
removeBot([name])Remove a bot (the bound one when unnamed). Returns boolean
getUsername()Bound bot's name, or ""

addBot accepts full token lines (token|mac|rid|wk|platform shapes and a leading @name segment are understood). A created bot is not logged in — call bot:connect() or press Start.

local bot = addBot{ name = "worker1", secret = "token|mac|rid|wk" }
if bot then
    bot:connect()
end

Events

Subscribe with listen(name, fn), or define a global handler (function onChat(player, message)) — no subscription needed.

listen("chat", function(e)
    print(e.name .. ": " .. e.text)
end)

unlisten("chat")     -- drop one event's listeners
unlisten()           -- drop all of this script's listeners

Registry verbs: listeners(), addEvent(name), removeEvent(name), removeEvents() (clear all), listenEvents(secs) (returns the interval in milliseconds), unlistenEvents().

onLogin is not an event — there is nothing to fire it from, and subscribing to it is rejected loudly.

The bot object

A bot answers methods (bot:say(...)) and properties (bot.name). Method names win over fields. You may store your own fields on the object.

Properties

PropertyMeaning
name, growid / usernameLabels and the account's GrowID
statusoffline | connecting | online | error | suspended (compare with BotStatus.online)
worldCurrent world name, "" when none
netid / netIdLocal player net id
x, yTile position
pingMilliseconds (0 = not measured)
gem_countGem balance as reported by the server
auto_farmRead: is the farm task queued?
auto_collectRead/write: the farm's AutoCollect filter
collect_rangeRead/write: collect radius, 1..5
auto_reconnectRead/write: automatic reconnect
pnb_punch_ms, pnb_place_msRead/write: PnB pacing, clamped 10..60000
levelAlways nil (not tracked)

bot:state() returns the exact engine state (connected, in world, entering world, …) when the five-word status is not enough.

Dialog example:

function onDialog(e)
    if e.name == "popup" and string.find(e.buttons, "acceptlock", 1, true) then
        bot:dialogReturn("popup", "netID|12|\nbuttonClicked|acceptlock")
    end
end
Nothing answers a dialog automatically — a reply the bot did not choose would be a guess. A dialog name containing | or control characters is refused.

Per-bot pacing

MethodRange
bot:walkms(ms)0..3000
bot:tilems(ms)0..2000
bot:chatms(ms)0..5000
bot:dropms(ms)0..2000 (drop/wear clock)
bot:warpms(ms)0..30000
bot:jitterms(ms)0..2000
bot:pacing()Read back: { walk_ms=, tile_ms=, chat_ms=, inventory_ms=, warp_ms=, jitter_ms= }

Out-of-range values return false, message (refused, not clamped). All settings persist with the bot.

Rotation world manager

MethodResult
wm.addFarm(world[, blockId])Add a farm world to the rotation
wm.removeFarm(world)Remove it

wm.addFarm("FARM2", 2)
wm.addStorage("STORAGE", StorageType.seed, 3)

wm.worlds lists the rotation. Farm entries carry the world and block id; the storage entry is the seed-storage world.

Webhooks

local hook = Webhook.new("https://discord.com/api/webhooks/...")
hook.username = "Zephyr"
hook.avatar_url = "https://example.com/avatar.png"
hook.content = "farm finished"
hook:send()

Webhook.new(url) returns a sender with username, avatar_url and content fields; send() posts them as JSON in the background — the script never blocks. Embeds, files and threads are ignored.

HTTP & files

CallResult
http.get(url)Background request; returns true when dispatched
http.post(url, body)Background request; body is sent as JSON
file.read(path)File contents, or nil, reason
file.write(path, content)true, or false, reason
read(path) / write(path, content)Same doors, shorter names
file.write("out/log.txt", "session ok\n")

local notes = file.read("data/notes.txt")
File access is confined to the scripts folder: a path that escapes it (../) is refused, not trimmed. Requests run in the background — the script continues while the network works.

Timers

local h = after(10000, function()
    print("ten seconds")

    print("tick")

sleep(500)

Errors

A script error is reported to the console and log, and the script stops. Codes: LUA_RUNTIME_ERROR, LUA_SCRIPT_NOT_FOUND, LUA_SCRIPT_EXISTS, LUA_SYNTAX_ERROR, LUA_TIMEOUT, LUA_SANDBOX_VIOLATION, LUA_MODULE_ERROR, LUA_SCRIPT_NOT_RUNNING.
